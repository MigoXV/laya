# W8A8 带标签精度评测

上一轮只用了 2 条测速输入；batch 16 是重复输入，不能当成 16 条独立精度样本。这里建立可复现的小测试集，用标准答案衡量任务精度，同时报告与原 FP16 的输出差异。

## 数据集

- [facebook/XNLI](https://huggingface.co/datasets/facebook/xnli)：中文和英文 `test` 各 200 条，共 400 道三分类文本推理题，标准答案是 entailment / neutral / contradiction。两种语言是同一批原始案例的平行翻译，不当成 400 条相互独立的语义案例。
- [zh-decision-bench](https://github.com/CodyQin/zh-decision-bench)：219 条中文案例、284 个问题，包含 179 条 MASSIVE 衍生语音路由，以及 40 条经人工审定的合成客服/内容审核案例，覆盖 choice / score / noul。使用[上游 Laya 适配格式](https://github.com/NandhaKishorM/laya/blob/main/research/evals/zh_decision_bench.jsonl)，文件保留 CC BY 4.0 来源声明。

共 **619 条请求、684 个带标签问题**；其中 **659 个分类/是非问题、25 个评分问题**。这不是用户真实业务测试集，也不是完整 XNLI；未知上游训练混合数据是否包含这些内容。本轮比较同一组模型权重的量化敏感性，不引用上游其他 checkpoint 的准确率冒充本模型结果。

XNLI 的 test 有 5010 行。固定 seed=42 随机选 5 个完整的 100 行块，再从这些候选中无放回抽取 200 个索引；中英共用索引，检查标准答案一致。每个下载文件的 SHA-256、Hub revision、抽样索引和来源记录在 [data/manifest.json](data/manifest.json)。评测读取已冻结文件并检查哈希，不按模型表现选择或删除样本。

## 对照与指标

1. `fp16-original`：项目原始 FP16 权重、autocast、完整未填充输入、batch 1。
2. `fp16-native-compile`：上一轮更快的 FP16 对照，展开决策头、关闭 autocast、整批执行、compile + CUDA Graph。
3. `w8a8-native-compile`：上一轮最快 W8A8 实现，动态逐 token 激活量化、逐输出通道权重量化、LayerNorm 量化融合、compile + CUDA Graph。

两条候选共用 batch 16 的一个固定最大长度/选项数 profile，padding 由 attention/marker mask 屏蔽，尾批复制合法行并丢弃额外输出；不截断原输入。任何格式或输入预算拒绝直接报错。评测中的 profile 与固定 27/512 token、2 个选项的性能样本不同，因此精度覆盖的是该实现的更多实际输入形状。

分类报告真实 accuracy、与原始 FP16 的准确率百分点变化、原对新错/原错新对数量和答案翻转率。评分按公开标准分数报告 MAE，不将连续期望值随意取整后混入分类准确率。概率另报最大/平均绝对误差、总变差、NLL 和 Brier。准确率变化的 95% CI 使用 4000 次按案例聚类的成对 bootstrap，同一中文案例的多个问题，以及中英平行案例，保持在同一组内。

动态量化不需要激活校准集；本轮不做 QAT，也不使用测试答案调参。动作头没有人工动作标签，只保存其输出，不能由此宣称动作准确率。

## 运行

```bash
# 显式选择原 FP16 仓库，供下列实验入口使用。
export LAYA_MODEL_DIR=/workspace/model-bin/MigoXV/laya-multilingual
# 首次建立/主动更新冻结数据，公网访问沿用环境代理。
poetry run python -m tests.w8a8.accuracy.prepare
poetry run pytest -q tests/w8a8/accuracy/test_metrics.py
CUDA_VISIBLE_DEVICES=0 poetry run python -m tests.w8a8.accuracy.evaluate
```

GPU 0 上运行离线精度评测，不计速度，不要求停止主服务，不改模型资产、主程序、依赖和服务配置。使用 [精简内核配置](../tuning.json)。每题的标准答案、三个实现的概率/原始 logits、API 回答和各任务汇总写入本目录 `results.json`。该输出不提交；本仓库只保留报告、评测代码和冻结标准答案数据。

## 实测结果

2026-10-03，A100-PCIE-40GB、Torch `2.8.0+cu128`。加载当前 `/workspace/model-bin/MigoXV/laya-multilingual` 的 FP16 权重；三个实现共用同一权重与标准答案。全部 619 条请求、684 个问题完成，无拒绝、无截断、无非有限输出。候选实际 profile 为 **B16 / L256 / K6**。

| 分类测试集 | 题数 | 原始 FP16 | 优化 FP16 | W8A8 | W8A8 相对原始变化 | 答案变化数 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| XNLI 中文 | 200 | 154/200（77.00%） | 77.00% | 153/200（76.50%） | −0.50 个百分点 | 12 |
| XNLI 英文 | 200 | 166/200（83.00%） | 83.00% | 169/200（84.50%） | +1.50 个百分点 | 4 |
| 中文决策 | 259 | 207/259（79.92%） | 79.92% | 204/259（78.76%） | −1.16 个百分点 | 7 |
| 合计 | **659** | **527/659（79.97%）** | **79.97%** | **526/659（79.82%）** | **−0.15 个百分点** | **23** |

另有 25 道中文客服紧急程度评分题，标准分数范围 0–2，MAE 越低越好：原始 FP16 **0.5027**，优化 FP16 **0.5027**，W8A8 **0.4849**；W8A8 相对原始连续评分的平均绝对变化为 **0.0519**。评分题单独统计，不进入上表分类分母。

### 怎么理解这些变化

优化 FP16 与原始 FP16 的 659 个分类答案全部一致，概率有小幅数值差异。因此本轮观察到的答案变化主要来自 W8A8，而不是批处理/编译本身。

W8A8 的 **23/659（3.49%）** 个答案发生变化：**10 道原对新错、9 道原错新对、4 道两者都错但选择不同**。净多错 1 道，不代表只有 1 道受量化影响。中文决策下降比总分更明显；其中 25 道客服路由从 16 道正确变成 15 道，单道就对应 4 个百分点，不能用这种小分项断言稳定退化幅度。

总体准确率变化的案例聚类 bootstrap 95% 区间为 **[−1.41, +1.19] 个百分点**，包含 0。中英 XNLI 是成对翻译，总计只有 419 个语义案例聚类；这里能报告小测试集上的点估计，不能将它解释成真实业务“只损失 0.15%”，也不能根据英文小样本宣称量化提高泛化精度。

| 输出指标 | 优化 FP16 相对原始 | W8A8 相对原始 |
| --- | ---: | ---: |
| 全部问题、全部选项的平均概率绝对偏移 | 0.023 个百分点 | **1.699 个百分点** |
| 最大单选项概率绝对偏移 | 0.741 个百分点 | **72.652 个百分点** |
| 分类 NLL（原始 0.6417，越低越好） | 0.6418 | 0.6496 |
| 分类 Brier（原始 0.3107，越低越好） | 0.3108 | 0.3145 |

概率平均偏移按所有 684 个问题的所有选项汇总，不等于平均准确率变化。最大偏移来自 `xnli-zh:xnli_132`：标准答案为 neutral，原始 FP16 给 neutral **17.20%**，W8A8 给 **89.84%**，此次从错变对。即使没有净准确率损失，也不能据此认为概率输出保持不变；如果业务直接使用置信度/概率门槛，必须继续验证。

本轮是未做 QAT 的动态 W8A8。结果支持继续实验，但还不足以把 W8A8 设为主程序默认。下一轮若做校准或 QAT，应使用独立训练/校准数据，并保留这里的冻结标准答案作比较，另补真实业务留出集。
